Connect your real database

This platform ships with a full production schema for Supabase (Postgres). Until a database is connected it runs on bundled demonstration data, clearly labelled. Connect it once and every visitor, order and listing lives in your own database.

Step 1 — create the database

  1. Create a Supabase project at supabase.com (free tier is fine to start).
  2. Open SQL Editor and run supabase/schema.sql from this repository. It creates 20 tables, 45 row-level-security policies, roles and triggers.
  3. Run supabase/seed.sql to load the starting catalogue, countries, tax rules and shipping routes as real rows you own and can edit.
  4. Create your staff accounts in Authentication → Users, then set each person's role in the profiles table (superadmin, sales, finance, logistics, agent, supplier, customer).

Both files live in the supabase folder of the repository. They are safe to re-run.

Step 2 — paste your connection details

Use the publishable / anon key only. Never paste a secret or service_role key into a browser: it bypasses every security rule.

What changes once connected

Real records

Listings, requests, quotations, orders, payments and shipments are rows in Postgres, shared by everyone, not one browser's memory.

Real accounts

Sign-in moves to Supabase Auth with server-side password hashing. Roles come from the profiles table.

Real security

Row-level security enforces it in the database: a customer cannot read another customer's order even if they call the API directly.

Real files

Inspection reports and customer documents go to a private storage bucket, readable only by the owner and staff.
